🔧 Key Design Decisions

1. No Role Classification

Decision: Do not classify players as "batsman" vs "bowler" vs "all-rounder"
Rationale: Role classification deferred to downstream WPA modeling where value is determined by actual impact, not arbitrary thresholds

2. No Minimum Thresholds

Decision: Include all players who batted/bowled ≥1 ball
Rationale: Maximum flexibility for downstream analysis; users can filter based on their needs
Benefit: Complete dataset; total_innings and total_overs columns enable easy filtering

3. Heuristic Definitions

  • Close Match: Decided by <15 runs margin
  • Quality Bowling: Economy <7
  • Weak Bowling: Economy >10
  • Competitive Total: Team score > league average (170.8)

Batting Stats (66 columns)

  • By Context (4): runs_in_wins, runs_in_losses, runs_in_close_matches, runs_competitive_total
  • By Innings × Phase (24): All 18 combinations with runs, balls, sr, boundaries
  • Additional (3): runs_vs_quality_bowling, runs_vs_weak_bowling

Bowling Stats (69 columns)

Similar structure with bowling-specific metrics: overs, wickets, economy, dot_ball_pct by phase

⚠️ Known Issues

Player Name Inconsistency

The source data contains inconsistent player name formatting:

  • Some players: Full names with spaces (e.g., "Shubman Gill", "V Kohli")
  • Some players: Initials without spaces (e.g., "SA Yadav" = Suryakumar Yadav, "SV Samson" = Sanju Samson)

Impact: Preserved in aggregated stats as we use exact names from source data

Recommendation: Handle name standardization in future data cleaning task before modeling

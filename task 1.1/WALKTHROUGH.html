What Was Done

1. Data Filtering

Original dataset: 278,205 ball-by-ball records (2008-2025)

Filtering applied:

  • ✓ Extracted year from date column and filtered for 2020-2025 seasons only
  • ✓ Removed super overs by filtering out:
    • Balls where over >= 20
    • Innings numbered 3-6 (super overs were coded as separate innings)
  • ✓ Total removed: 712 super over balls

Result: 99,076 ball-by-ball records from regular match play

2. Column Creation & Transformation

Created 25 columns in the final dataset:

Core Match Identifiers

  1. match_id - Unique match identifier
  2. innings - Innings number (1 or 2)
  3. over - Over number (0-19)
  4. ball - Ball number within over (1+, can exceed 6 due to wides/no-balls)

Players

  1. batsman - Batsman on strike
  2. bowler - Bowler
  3. non_striker - Non-striker batsman

Ball-by-Ball Metrics

  1. runs - Total runs scored on this ball (batsman runs + extras)
  2. wicket - Wicket indicator (1 if dismissal, 0 otherwise)
  3. boundary_type - Type of boundary ('four', 'six', or 'none')

Cumulative Match State

  1. current_score - Running score up to this ball (cumulative within innings)
  2. current_wickets - Running wickets up to this ball (cumulative within innings)
  3. balls_remaining - Balls remaining in innings (120 - current ball number)

Match Context

  1. phase - Match phase:
    • 'powerplay' (overs 1-6)
    • 'middle' (overs 7-15)
    • 'death' (overs 16-20)
  2. match_winner - Team that won the match (derived from final scores)
  3. final_score_innings1 - Final score of first innings
  4. final_score_innings2 - Final score of second innings

Team Information

  1. batting_team - Team batting in this ball
  2. bowling_team - Team bowling in this ball

Metadata

  1. season - Year of the match
  2. date - Match date

Quality Flags

  1. is_high_score - Flag for unusual high scores (>250)
  2. is_low_score - Flag for unusual low scores (<100)< /li>
  3. dismissal_kind - Type of dismissal (if any)
  4. player_dismissed - Player dismissed (if any)

3. Match Winner Logic

Match winner determined by comparing final scores:

  • If final_score_innings1 > final_score_innings2 → Batting first team won
  • If final_score_innings2 > final_score_innings1 → Chasing team won

Key Implementation Details

Super Over Handling

Discovered that super overs were coded in two ways:

  1. As over >= 20 (traditional coding)
  2. As separate innings (innings 3, 4, 5, 6)

Both filters were applied to ensure complete removal of super over data.

Cumulative Calculations

Used pandas groupby().cumsum() to calculate running totals within each innings:

df['current_score'] = df.groupby(['match_id', 'innings'])['runs'].cumsum()
df['current_wickets'] = df.groupby(['match_id', 'innings'])['wicket'].cumsum()

Phase Categorization

Phases assigned based on over number:

  • Powerplay: Overs 0-5 (first 6 overs)
  • Middle: Overs 6-14 (overs 7-15)
  • Death: Overs 15-19 (overs 16-20)
